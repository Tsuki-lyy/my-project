### 4.4 中文路径下 cargo 构建

⚠️ **踩坑记录**：实验目录路径 `F:\GMD\软件工程导论\作业\实验\sqlrustgo` 含中文字符。默认 cargo 在子进程运行 build script（proc-macro2、quote 等）时偶发 `Os { code: 0, kind: Uncategorized, message: "操作成功完成。" }` 错误。

**解决方案**：

```powershell
$env:CARGO_TARGET_DIR = "C:\sqlrustgo-build"
cargo build --all
```

将编译产物目录设置到非中文路径，问题解决。已在 README 与 docs 中标注该最佳实践。

## 6. 遇到的问题与解决

| # | 问题 | 原因 | 解决 |
|---|------|------|------|
| 1 | `cargo build` 在中文路径下 build script 失败 | Windows 文件系统与中文路径在子进程 exec 时兼容性 | 设置 `CARGO_TARGET_DIR=C:\sqlrustgo-build` |
| 2 | Parser 内部 `expect_symbol(';')` 拒绝无分号 SQL | 实验 demo 中 `CREATE TABLE users(...)` 不带 `;` | 改用 `consume_optional_semicolon()` 允许末尾 `;` 可选 |
| 3 | `Value` 未实现 `PartialOrd` 触发编译错误 | `WHERE age > 18` 比较需要 `<` / `>` 算子 | 给 `Value` 增加 `PartialOrd + Ord` 实现（含 `rank()` 跨类型次序） |
| 4 | `Database` 内同时持有 `Box<MemoryStorage>` 与 `Executor` 触发 lifetime 错误 | `Executor::new` 接受 `Box<dyn>`，双重 Box 没有意义 | 简化为 `Database { executor: Box<Executor> }` |
| 5 | Edit 工具多次修改大段函数体未生效 | 编辑工具在多行长字符串替换上偶发失配 | 改用 `Write` 工具整文件重写 |
