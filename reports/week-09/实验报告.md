## 4. 遇到的问题和解决方法

### 4.1 直接推送被拒绝

**问题**：尝试直接推送到 `develop/v1.4.0`
**解决**：通过 PR 流程合并代码

### 4.2 合并冲突

**问题**：两个分支同时修改 `book.rs` 文件
**解决**：
1. 识别冲突标记：`<<<<<<< HEAD`, `=======`, `>>>>>>>`
2. 手动合并代码（保留两个功能）
3. 提交并推送解决结果

## 5. 思考与反思

### 5.1 分支保护的必要性

- **安全性**：防止意外提交破坏代码
- **质量**：强制审查流程，提高代码质量
- **流程**：建立规范的代码合并流程

### 5.2 多AI协同中人类角色的体会

1. **架构师**：制定统一规范
2. **协调者**：分配任务，避免冲突
3. **审核者**：把关代码质量
4. **决策者**：解决冲突和争议

## 6. 附录：Git操作记录

```bash
# 步骤1：分支分析
git branch -a
git log --oneline --graph --all --decorate --max-count=20
git fetch origin
git branch -r

# 步骤2：创建功能分支
git checkout develop/v1.4.0
git checkout -b feature/week9-lab
git commit --allow-empty -m "chore: init"
git push origin feature/week9-lab

# 步骤5：功能开发
git checkout -b feature/ai-book-category
# 修改代码...
git add src/main.rs src/models/book.rs src/models/mod.rs
git commit -m "feat: add BookCategory"
git push origin feature/ai-book-category

# 步骤6：模拟冲突
git checkout develop/v1.4.0
# 修改代码...
git commit -m "feat: add description"
git push origin develop/v1.4.0
git checkout feature/ai-book-category
git merge origin/develop/v1.4.0
# 解决冲突...
git add src/models/book.rs
git commit -m "fix: resolve conflict"
git push origin feature/ai-book-category
```
